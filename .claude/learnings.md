## 2026-11-18 - Environment quirk
The PDF has no text layer (every page is an image), and this Mac has no `pdftoppm`/`pdftotext`. `swift` is also broken here (Command Line Tools module redefinition error), so Swift scripts will not compile.
What works: `osascript -l JavaScript script.js <pdf> <outdir>` using PDFKit through the ObjC bridge to render pages to PNG. Then read the PNGs.

## 2026-11-18 - Shell (lane 2) patterns
- Fontsource CSS is unicode-range split. The peso sign (U+20B1) is in the `latin-ext` face of Reddit Mono, which the browser only fetches when a price is on screen. Verified with CDP `CSS.getPlatformFontsForNode`: the peso renders in Reddit Mono, Cinzel never gets it. Vite rewrites a `<link rel=preload href="/node_modules/@fontsource-variable/.../cinzel-latin-wght-normal.woff2">` in index.html to the hashed asset, so the title-face preload needs no plugin.
- Pager pages are `inert` unless active: a Tab stop on an off-screen page makes the browser scroll the track sideways. Indicator/arrows/jump notes call `goTo(i, {focus:true})` and the active-page effect moves focus to `[data-page-heading]`; swipes never move focus.
- Cover portal: the cover is a track page, so the "arch floods the screen" tween ends in a hand-off behind `.pager__veil` (same red as the arch) and an instant `scrollTo` to page 1. The veil, not the pager, hides the cut.
- A badge beside an item name squeezes long names on 390px (17 "Unli rice" pills on one page). Badges sit on the description line instead.
- Headless Brave drives well over CDP with Node 24's global `WebSocket` (no puppeteer needed): `Input.synthesizeScrollGesture` for real swipes, `Emulation.setEmulatedMedia` for reduced motion, `Network.emulateNetworkConditions` + `Emulation.setCPUThrottlingRate` for an LCP check.

## 2026-11-18 - Stage and Anatomia (lane 3) patterns
- Circle crop needs no image size: frame `left:50%; top:50%; width:(50/r)%` of the plate box, `translate(-cx*100%, -cy*100%)` of its own size (`cropFrame`). The same frame, clipped with `clip-path: ellipse()` on the `<img>` only, is an Anatomia layer that sits exactly on its own pixels at z=0.
- photos.json holds ONE plate per file. `alsoFor` dishes (sisig, pinakbet, hot choco...) have their circles in `photos.report.md` only; they live in `stageLogic.ts` (`ALSO_FOR_PLATES`) until the manifest gets a field for them.
- True isometric is `rotateX(55) rotateZ(-35)` (Z applied to the point first). GSAP's own transform order is the reverse, so Anatomia writes the transform strings itself. All motion tweens plain numbers in a state object; one `apply()` writes DOM transforms and the SVG leader lines from the analytic `project()` (no getBoundingClientRect while dragging).
- Never put `touch-action` on the stage: the pager swipes with native scroll-snap and a swipe that starts on the stage must still scroll. Draggable on a detached proxy div with `trigger: view`, dx = `this.x - this.startX`.
- React 18 warns on camelCase `fetchPriority` on `<img>` (needs lowercase, which the types reject): skip it, `loading="eager"` is enough.
- Brave CDP from Node needs `--remote-allow-origins=*`, otherwise the WebSocket never opens and node exits 13 silently. To test lane 3 inside the real shell without editing lane 2's files: a throwaway vite config with an inline plugin that rewrites the `StageSlot` import in `CategoryPage.tsx`.
- Chrome keeps a FAILED dynamic import in its module map for the page's life: resetting `React.lazy` alone does not make a retry succeed. The Anatomia pill says "Try again" once, then "Reload". `loading=lazy` is not a gate on a horizontal pager (Chrome counts off-screen pages as near): a stage renders no `<img>` until it has been near once. A swap interrupted by leaving the page must reset the plate in the `!active` branch, or it returns spun out at opacity 0. Headless Brave profiles are ~100 MB each: reuse one dir per run, or the disk fills (it did).

## 2026-11-18 - Pager settle check and headless driver hygiene
- The reported "reduced motion: after the first swipe, swipe back and vertical scroll stop working" does NOT reproduce on f6f810c. Tried at 390x844 touch: `Input.synthesizeScrollGesture` and manual `dispatchTouchEvent`, 6 pages forward and back, stage start vs list start, reduced emulated before and after load, mouse (desktop) gestures, ArrowLeft/Right, arrow buttons, the cover portal tap (lock released in `finish`), a 40-round random swipe storm (interrupted flings, tiny drags) and 6x CPU throttle. Invariant held every time: at rest the only non-inert page is the page under the viewport and `scrollLeft === index * width`. The earlier failure was most likely the driver (three headless Brave instances from older drivers were still alive after 11 hours and the old harness was starved), not the settle logic. If it comes back, first check `inert` on the pages and `[data-locked]` on the track: a stale active page leaves the new page inert (vertical scroll dead), a stuck lock sets `overflow-x:hidden`.
- What settle must guarantee: `scrollend` (or 120 ms of scroll silence where it is missing) is the only thing that moves `activeIndex`, so every scroll that changes the page must end in one of those. Do not add a second writer.
- Headless drivers: one `mkdtemp` profile under the scratchpad, `--remote-debugging-port=0` and read the port from `<profile>/DevToolsActivePort`, spawn detached and kill the whole process group (TERM then KILL) BEFORE `rmSync` of the profile, cleanup in `finally` plus SIGINT/SIGTERM/SIGHUP/exit hooks. A leaked headless Brave keeps running after its profile folder is gone: find them with `ps -axo pid,command | grep user-data-dir=/private/tmp/claude-503`.
- Driver traps on this Mac: zsh does not word-split `$args` (a "reduced" run silently ran as "full": print `matchMedia('(prefers-reduced-motion: reduce)').matches` in the first log line), there is no `timeout` binary, and `--force-prefers-reduced-motion` does not flip `matchMedia` in this headless build (use `Emulation.setEmulatedMedia`).

## 2026-11-18 - Anatomia loader seam and the retry race
- `anatomiaLoader.ts` now exports `createAnatomiaLoader(importer)` (load / preload / reset); the module-level `getAnatomia`, `preloadAnatomia`, `resetAnatomia` wrap one instance built on the real `import()`. Tests in `anatomiaLoader.test.ts` hand in a fake importer, no React or DOM needed.
- A late failure of an old import can only clobber a newer one through `reset()` (a plain `load()` while one is in flight shares it). The catch handler therefore clears `pending` only if `pending` is still that same attempt. Red-first proof: without the identity check the race test saw a third import.

## 2026-11-18 - Stage focus request and Reload after the first chunk failure
- A tile tap parks a focus request (`focusSlot = { id, slot }`) for the swap to ITS dish. It cannot be cleared in the swap effect's cleanup (cleanup runs after `onPick` has already parked the request for the new run). Instead each effect run drops a parked request that is not for `wantedId`, or when the wanted dish is already on the plate, or when the page is not active. `commit` only uses it if `id === nextId`. Reproduced red in headless Brave before the fix: tile tap then a different list row, tile tap then the already-shown row, and tile tap then leaving the page each sent focus to a tile on the next list-row swap.
- Chrome caches a failed dynamic import for the page's life (the OLD two-step "Try again" press fired no second network request), so the Anatomia button now says "Reload" after the FIRST failure and calls `location.reload()`. This supersedes the "Try again once, then Reload" line in the Stage patterns entry above. `usePager` mirrors the settled page into the hash with `replaceState`, so the reload lands on the same page (checked: `#breakfast` kept, page 1 active).
- Driver traps: `Page.navigate` to the same URL (only the hash equal) is a same-document navigation, so React state survives between "fresh" scenarios: go to `about:blank` first. Vite dev listens on `[::1]`, so reach it as `localhost`, not `127.0.0.1` (a different server can own 127.0.0.1 on the same port).

## 2026-11-18 - Publishing to GitHub Pages
- Live at https://bored-six.github.io/la-roma-digital-menu/. `.github/workflows/deploy.yml` (npm ci, npm test, npm run build, upload `dist`, deploy-pages) runs on every push to main. Pages must be switched to the "GitHub Actions" source BEFORE the first push, or the deploy job has no site to publish to: `gh api -X POST repos/<owner>/<repo>/pages -f build_type=workflow`. The relative `base: './'` makes it work from the `/la-roma-digital-menu/` sub-path with no config.
- Before the first push the history was rewritten with `git filter-branch` to use the GitHub noreply author email and to drop `reference/` (the client's menu PDF and renders; the site does not need them: only comments mention it). `reference/` is now in `.gitignore` and stays on the local disk. The repo-local `user.email` is set to the noreply address so new commits do not leak the personal address.
- `git filter-branch` ends by checking out the rewritten HEAD, which DELETES from the working tree the files it removed from history (`reference/` vanished from disk). Take a `git bundle create ... --all` backup first and restore the folder from it; it was byte-identical afterwards.
- The first HTTPS push died with "RPC failed; HTTP 400" (about 3.5 MB of history with photos) until `git config --local http.postBuffer 524288000`.
- A fresh clone (`git clone . /tmp/x && npm ci && npm test && npm run build`) is the right pre-push check: it proves nothing depends on ignored local files such as `reference/`.

## 2026-11-19 - Cover first-load weight
- Measured on the live site: first load was 1.2 MB, and ~850 KB of it (7 dish photos for page 1: chicksilog hero plus the silog and noodle tiles) loaded on the COVER, because `Pager` marked page +-1 as `near` and a near stage renders its photos eagerly. They started right after the fonts, so on a slow phone link they competed with the fonts and the cover intro animation.
- Fix: `isNearPage(index, activeIndex, neighboursReady)` in `lib/pager.ts`. The current page is always near; neighbours only after `whenSettled` (`lib/settle.ts`: page `load` then idle, or first user input, or a 5 s cap). `useNeighboursReady` wires it into `Pager`. Fast tap on "Open menu" still works: the tap is the first input, and page 1 is then the active page anyway.
- `whenSettled` takes an env seam (`SettleEnv`) like `createAnatomiaLoader(importer)`, so it is tested without a DOM. `browserSettleEnv()` is the real one.
- Only fonts used on the cover are preloaded in `index.html` (Cinzel, Familjen italic for the tagline). Bricolage and Reddit Mono are not on the cover; preloading them would compete with the arch image and JS on a slow link.
- Dev note: the Vite dev server serves unbundled modules, so load timing there is not representative. Measure with `npm run build` then `npm run preview` (launch.json: `la-roma-preview`, port 5198).

## 2026-11-19 - Blank page right after a deploy (stale HTML, deleted bundle)
- GitHub Pages serves `index.html` with `cache-control: max-age=600` (10 min) and each deploy REPLACES the whole site, so the old hashed bundle (`assets/index-<hash>.js`) 404s straight away. A browser that cached the old HTML in the last 10 minutes asks for the old bundle, gets a 404 and shows the empty cream background, no error on the page. Reproduced in the in-app browser right after the 74eea16 push: console 404 for `index-sbmMImHr.js`, blank page; a fresh URL (`?fresh=1`) loaded fine.
- Fix for the viewer: hard refresh (Cmd+Shift+R, on a phone close the tab and reopen) or wait up to 10 min. Nothing to fix in code: Pages does not let us set headers or keep old assets. Do not "fix" it with a service worker; not worth it for a showcase site.
- Consequence for pushes: every push to main opens a ~10 min window where returning visitors can see a blank page. Push in one batch, and tell the user before pushing if they are about to show the site to someone.

## 2026-11-19 - Photos from Gemini and from real product shots
- Gemini photo workflow: one self-contained prompt per dish in `docs/gemini-photo-prompts.md`; images go through `sips -Z 900` (lower the JPEG quality until under 150 KB), a row in `photoSizes.ts` and an entry in `photos.json`. The plate circle comes from a grey-scale `cv2.HoughCircles` on a 500 px copy (matches the hand-made circles within about 0.01); bowls with an inner red line fool a saturation-based detector (it finds the inner line), so check bowls by drawing the circle on a contact sheet. Drinks need a bigger circle that holds glass, garnish and saucer (r about 0.31 to 0.37).
- Same file name = same photo: `Beef Steak` and `Beef Liver Steak` both look like soy-and-onion beef, so check which one the user means before filing a photo (one was filed wrong and renamed).
- Cutting a bottle out: grabCut is not good enough (white label on a white table, glass overlap). macOS Vision subject lifting is: `osascript -l JavaScript` with `VNGenerateForegroundInstanceMaskRequest`, then `obs.generateMaskedImageOfInstancesFromRequestHandlerCroppedToInstancesExtentError(indexSet, handler, true, err)` (the short selector without croppedToInstancesExtent does not exist) and an `NSBitmapImageRep` PNG write. Python has no PyObjC here. It lifts the glass together with a bottle that touches it.
- A clean maple background for composites: blur one of our own photos heavily and add faint anisotropic noise (horizontal streaks). Mirror-tiling a strip leaves visible symmetric blotches.
- Wikimedia Commons: the search API is fine at one query per 2.5 s; `upload.wikimedia.org` answers 429 to repeated originals, the 1280 px rendering (`iiurlwidth=1280` thumburl) goes through. Photos with CC BY / CC BY-SA need credit (`docs/photo-credits.md`); CC0 needs none.

## 2026-11-19 - Italian type swap (supersedes the Cinzel / Bricolage / Familjen / Reddit Mono notes above)
- Now Bodoni Moda (titles, names, prices, labels) + EB Garamond Italic (descriptions). Chosen from a three-way specimen at phone width using real menu text; the reasoning and the rejected sets are in `design-system/DESIGN.md`, Type. The old grotesque set read as a tech product.
- Peso sign: checked with fontTools `getBestCmap()` (needs `python3`, works on the fontsource woff2 files). Bodoni Moda, Libre Bodoni and Marcellus have no U+20B1; Cormorant Garamond and EB Garamond do, but only in latin-ext (114 KB for EB Garamond). `src/assets/fonts/la-roma-peso.woff2` is that one glyph (pyftsubset, 1 KB, weight axis kept; command in DESIGN.md). Vite inlines assets under 4 KB, so it ends up as a data URI in the CSS: no extra request, and the `unicode-range` is only a guard. Every font stack that can print a price lists "La Roma Peso" FIRST: Bodoni's latin-ext face claims U+20A0-20C0 (so it claims the peso sign) without having the glyph, and listed before the subset it made the browser fetch 25 KB of Bodoni latin-ext on every price page (seen in `performance.getEntriesByType('resource')` on the production preview).
- Bodoni Moda needs `/opsz.css` and the browser's `font-optical-sizing: auto`: the hairlines thicken at 11 px by themselves. Do not set `font-variation-settings: 'opsz'` by hand (the three old calls were removed).
- Garamond runs small: descriptions went 14 -> 16 px, the glass card text 13 -> 15 px, the cover tagline 15 -> 17 px.
- Stage name fit: the old fixed size steps by name length (34/30/26/22 px) were tuned for wide Cinzel capitals and made "Barako Brewed Coffee" wrap onto the photo. Now `fitFontSize` (`lib/fit.ts`, tested) does the maths and `components/stage/fitTitle.ts` measures one nowrap line and re-fits on box width change and on `document.fonts` `loadingdone` (a late web font changes the text width). It keeps 3 % slack because SplitText cuts the name into inline-block letters, which loses kerning: an exact fit (28 px in a 295 px box) wrapped to two lines in the real browser.
- Rows: `.lr-leader` in stage.css has `align-self: baseline`, which beats the container's `align-items`, so with `last baseline` (a name that wraps) the leader stayed on line 1 while the price went to line 2. The row rule sets both `align-items` and `align-self` to `last baseline` inside `@supports`.
- Tooling: `npm i --no-save` is the clean way to try font candidates (package.json untouched). A Bash `cd` into node_modules persisted as the working directory for later calls: use absolute paths. Browser-pane screenshots at a 375 px viewport are 1x, the earlier 750 px-wide ones were 2x: do not compare stroke weights across them.
- Measuring text for a fit: `el.scrollWidth` is never smaller than `clientWidth`, so with a 3 % slack it made every name look too wide and shrank "Hawaiian" to 32.5 px instead of the 34 px token (caught by the reviewer, confirmed in the browser). Measure the text itself: a `Range` over the contents, `getBoundingClientRect().width`, with `white-space: nowrap` set. jsdom has no layout, so the unit test cannot see this: check `getComputedStyle(title).fontSize` for a short and a long name in the browser. Observe the title's PARENT with ResizeObserver, since a refit changes the title's height.
- Google Fonts families are named "Bodoni Moda" / "EB Garamond"; fontsource's are "... Variable". The tokens list both so the dev lab and preview pages (Google Fonts) match the app (fontsource).

## 2026-11-19 - Dish photos were the page weight: WebP variants
- Measured (phone viewport, production build): page 1 loaded 7 photos, ~920 KB, and the page next to it another ~900 KB. Every one was the 900 px / ~130 KB JPEG master, including the six option tiles that show it in a 47 px disc (60-109 CSS px wide with the crop). The plate itself shows at 267 CSS px.
- Fix: `scripts/photo-variants.sh` (cwebp) builds `public/dishes/<slug>.webp` (same pixel size, q80, 3.2 MB for all 80, heaviest 55 KB) and `public/dishes/t/<slug>.webp` (320 px wide, q75, ~9 KB each, 750 KB for all). `stageData.ts` `photoUrl` now returns the hero WebP, `thumbUrl` the thumb; `PhotoFrame variant="thumb"` is used by `OptionTiles`. photos.json still names the JPEG master, so `photoSizes.test.ts` keeps reading master headers. Result: page 1 plus neighbour = 13 files, 176 KB, down from ~1.7 MB (about 90% less). 1:1 crop compare at q80 showed no visible loss.
- `photoVariants.test.ts` guards the invisible failures: a variant missing on disk (one dish silently 404s), wrong pixel size or aspect ratio, and the byte budgets (hero 100 KB, thumb 20 KB). It parses the WebP header itself. Consequence for the photo workflow: after adding a master you MUST run the script and commit the variants, or CI (and the deploy) fails. Written into CLAUDE.md.
- Masters are still in `public/` so they still ship in the Pages artifact (about 10 MB), but nothing requests them. Moving them out of `public/` would trim the deploy; it needs `photoSizes.test.ts` pointed at the new folder. Not done: no user-visible gain.
- Vite dev trap: files added to `public/` while `npm run dev` is running are not picked up: the dev server answered the new `.webp` heroes with the SPA fallback (a 2 KB `index.html`, `naturalWidth` 0, blank plate). Restart the dev server. The production build was unaffected. Also a hash-only navigation (`#breakfast`) in the browser pane keeps the old page and old JS: navigate with a changed query string (`?fresh=1#...`) for a real reload.
- No `avifenc` here, and WebP is already ~60-80% smaller than the JPEGs; AVIF would save a little more at the cost of a fallback chain. Not worth it for this site.
